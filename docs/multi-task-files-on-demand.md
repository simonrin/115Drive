# 多任务与文件随选实施记录

## 约定（2026-11-07）

- 一个客户端、一个 115 账号、多个独立任务；每个任务选择本地/云端目录。
- `always_keep`：原有、本地新增和云端新增文件均默认完整下载并固定。
- `online_only`：云端新增只建占位；本地内容在上传和版本核验成功后才允许释放；打开后缓存默认闲置 24 小时回收。
- 文件显式设置 > 最近父目录显式设置 > 任务默认值。修改默认值不覆盖显式例外。
- 活跃句柄、待上传、冲突、失败和固定文件不能自动回收。
- 本地同步根不能重叠；首版同账号云端映射也不能重叠。子目录策略无需注册嵌套同步根。
- 任务状态、索引、操作记录和锁独立。账号访问共用限速。
- 当前 bisync 任务及历史保持兼容；未经核验不得原地切换或重置历史。

## 实施顺序

1. 新增任务配置、路径归属检查、策略继承、隔离持久状态和回归测试。
2. 接入 Windows Cloud Files API：注册、占位、原地接管、下载回调、固定、释放与状态查询；以独立本地后端验证真实 NTFS 行为。
3. 新增占位感知同步协调器及 115 后端：完整目录核验、内容版本、上传下载、冲突及中断恢复。
4. 接入控制台/原生设置：创建、策略、暂停/恢复、状态；启动生命周期、构建和源码导出。
5. 旧测试回归、双任务隔离验证、真实云端测试及迁移检查。只有实际通过的范围才标记完成。

## 验收

- 同账号两个独立目录能采用不同默认策略，手动例外跨重启保留。
- 枚举仅联机文件不下载正文；打开才触发真实下载并核验内容。
- 固定文件离线可读；释放空间后逻辑大小和云端内容不变，磁盘分配减少。
- 修改上传失败不能清理；云端清单不完整、重复名称、根身份变化时停止变更。
- 删除与释放语义独立；同时修改保留冲突版本；失败重试不丢操作记录。
- 一个任务暂停/故障不覆盖另一任务的状态；同路径第二实例无法启动。
- 活跃旧目录不进入任何新引擎测试。真实测试全部使用本次独立目录。

## 使用方式

1. 在 115 网盘中建立两个互不包含的目录，例如 `/工作资料`、`/归档`。
2. 在设置的“同步与备份”页点击“添加同步任务”，分别选择互不包含的本地目录。原有同步盘和新增任务统一显示在“同步文件夹”列表中。
3. 工作资料选择“始终保留”，归档选择“仅联机”。保存后任务处于暂停状态；启动后先核对云端，再注册同步根。
4. “保留策略”可修改任务默认值、缓存时间，或填写文件/子目录相对路径设置例外。选择“继承”可取消例外。右键的固定/释放选择写入同一份策略配置。
5. 暂停只停止当前任务；已下载文件仍能离线读取，未下载占位文件需要恢复任务后打开。重新登录前需要暂停所有任务并等待工作线程退出。

每张任务卡片显示本地/云端路径、保留策略、状态和独立操作。原任务保留“更改位置”，新增任务提供“保留策略”；页面下方“通用偏好”管理 Windows 登录时自启动。原有“同步任务”入口已合并到此页，任务配置、同步方式和历史不随界面合并而改变。

`always_keep` 覆盖原有本地、本地新增和云端新增文件；云端更新先完整下载核验，再替换旧的离线版本。`online_only` 的云端新增文件不下载正文，本地内容必须上传并核验成功才可回收；默认缓存闲置 24 小时，设置为 0 时在空闲且核验通过后尽快回收。冲突副本默认固定，只有针对该副本明确选择“仅联机”才取消保护。

本地需要 Windows x64、支持 Cloud Files API 的系统及 NTFS。一个任务一个同步根；任务目录不得与程序目录、原有任务或另一任务交叠。云端映射首版同样禁止交叠。

## 多任务检查与调度（2026-11-08）

新任务空闲时将云端检查等待时间从约 15 秒逐级延长至 30、60、120 秒，各任务略微错开。检测到本地内容或策略变化时提前唤醒，连续变化会合并处理。云端修改的发现时间可能达到空闲等待上限，再加实际扫描和排队耗时。

同账号临近到期的随选任务现在会进入同一检查批次，收集窗口约 2 秒；本地变化和策略修改可以提前放行。本批共用短时账号连接核验、合并相同目录的重复查询，但不同目录仍分别读取完整分页。任务分别完成，不等整批完成后才同步；暂停只取消当前任务。管理器每轮统一读取任务配置。详见 [合批检查验收](task-batching.md)。

本地使用 Windows 文件变化通知，60 秒完整扫描兜底；监听异常时降级为 2 秒轮询并重试监听。通知与缓存只用于决定何时检查，实际同步仍重新核验完整云端清单和本地状态。仅联机的缓存时间控制本地正文回收，不是扫描间隔。

元数据请求公平排队，上传、后台下载和打开文件的按需下载使用独立通道。新任务最多同时进行 1 个上传、1 个后台下载、2 个交互下载；大文件传输不占用其他任务的元数据通道。原有 bisync 工作进程和调度设置保持不变，尚未统一进同一个跨进程账号调度器。

状态内容未变化时不重写同步基线；关键事务仍原子写入并 fsync。下载和释放前后核验目标祖先目录及父目录，避免重复扫描无关子树，不使用旧缓存来批准删除、覆盖或释放。实测及范围见 [调度优化记录](task-scheduling-optimization.md)。

批次只复用 5 秒内成功核验的结果，服务于初始只读扫描。云端身份提交、下载、释放、本地删除及仅联机占位更新仍重新核验；恢复扫描绕过批次缓存。缓存限制为最多 128 个已完成条目、4,096 条目录记录，超大目录结果只共享当前在途请求，不留在已完成缓存中。

## 并发提交与恢复

新 CfAPI 任务先将内容上传到唯一暂存名称并核验，再按不可变文件 ID 保存旧版本、提升新版本；不直接覆盖现有路径。115 的同名改名会自动编号，提交后必须再次核验目标 ID。另一客户端抢先写入时保留双方内容并产生冲突，不把竞争结果当作成功覆盖。

被替换或删除的云端版本以 `_twodrive-version-…` / `_twodrive-deleted-…` 名称保留，会占用云端空间；暂不自动过期清理。这些版本不显示在本地同步目录中，可在 115 网盘查看。`_twodrive-stage-…` 是未完成事务；发现它时停止普通变更扫描，拥有该事务的客户端先恢复提交。不要手工改动这些内部名称；异常时保留现场和操作日志。

原有 bisync 的恢复设置保持不变。新事务不是服务端原子条件写入，也不能阻止其他客户端主动删除历史版本。115 原生改名不能改变扩展名；这种操作会安全停止，可通过复制为新文件并在同步成功后删除旧文件完成。

## 开发版边界与后续发布检查

- 已完成所列 GB 级压力、进程强杀/重启及跨客户端修改验收；尚未进行整机物理断电、磁盘硬件故障、大目录性能与长期稳定性测试。
- 实际同步仍为完整目录核验；已减少空闲检查、无变化写入及单文件操作的无关扫描，目录级增量云端索引和与旧工作进程统一调度尚待优化。
- 文件/目录显式策略目前按相对路径保存；改名保留内容，但策略自动跟随改名尚未实现。
- 暂不提供一键把原有 bisync 任务转换为 CfAPI，也不提供含未下载文件任务的一键卸载。需要先完整下载并核验后才能解除占位管理。
