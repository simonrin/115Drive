# 大目录核验优化（2026-11-12）

目标：同一网盘账号作为一组调度，缩短启动可用时间，去掉重复整树读取和无意义排队；保留原任务 ID、路径、策略、文件及同步基线。

实施顺序：

1. 启动只读取根目录身份和根部健康标记，完整目录核验放在第一轮检查。目录缺失、账号变化、健康标记异常仍停止；普通同步变更在完整清单核验后执行。已有待恢复事务继续按原身份、版本及持久日志进行独立新鲜核验。
2. 同账号统一检查轮次。小目录检查完成后等待本组扫描完成再安排普通下一轮；各任务取得清单后独立处理文件，本地变化可提前触发。完成元数据核验后即释放组内扫描名额，不等待大文件传输。
3. 普通清单只读取权威 115 清单；将 OpenList 路径缓存刷新和一致性核验移到实际传输前的目标目录及祖先路径。删除、覆盖、冲突处理、释放空间仍执行新鲜的身份/版本核验，不使用跨轮次缓存批准变更。
4. 长扫描支持在目录/分页间取消，并报告节流后的进度与请求计数。不提高网盘请求频率，不根据不可靠的父目录时间跳过子树。

验收：大树请求计数和启动边界；账号分组、暂停/恢复、失败任务隔离、本地变化优先与传输不阻塞其他任务；缓存错配、云端并发变化和旧状态回归；原生隔离验收；备份后部署运行服务，对六个现有任务验证启动时长、完整轮次、无变化写入和原同步基线保留。

部署前后均保留诊断记录。既有 `runtime/health-check-20261112/` 为优化前观测，不作为优化后结果。
