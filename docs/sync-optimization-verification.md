# 同步优化验证记录

以下为 2026-10-28 在 Windows 本机和已授权 115 会话中完成的两批验证。测试使用专门创建的临时同步子目录，结束后清理测试文件并恢复正常后台任务。公开记录不包含账号、凭据、文件清单或实际运行日志。

## 第一批：索引写入、异常分类与时间拆分

- 索引正文仅在内容变化时写入；独立核验记录通过 SHA-256 绑定正文，缺失或不匹配时不会确认同步成功。
- 临时连接错误保留索引并退避重试，结构不一致重建索引，需要处理的问题等待操作。
- 最近检查、同步成功和已确认文件传输分别记录；单纯检查不会刷新同步成功时间。
- 当时通过 112 项 Python 测试、4 个 Go 包的针对性检查和 32 项托盘自检。

## 第二批：本地事件监听与定期扫描

- 通过 125 项 Python 测试，包含 Windows 原生递归事件、真实缓冲区溢出、监听读取取消、失败重试和同步期间的并发修改。
- 真实双向新增、同大小修改和删除均通过；上传内容经云端 SHA1 和下载回读核对。
- 在临时验证进程中丢弃已收到的通知提示，定期扫描仍发现文件并在约 72 秒内完成上传。
- 取消该进程自身的 Windows 目录读取请求后，自动退回轮询、发现待上传文件并重新建立监听；下载回读内容一致。
- 通过临时 HTTPS CONNECT 转发关闭真实 TCP 连接，验证同步连接中断后的自动恢复；恢复连接后约 47 秒完成同步，无需手动触发，仍使用增量索引。
- 连续三轮空闲云端检查耗时约 72 秒，其间只发生 1 次完整本地扫描，大型索引和本地快照均未重写。
- 初始化身份、同步配置和筛选规则保持一致，测试结束后正常计划任务恢复。

## 结果边界

本次首个上传等待约 316 秒，后续变化传播约 20–36 秒；这些是当时的观测值，不是延迟保证。完整比对仍执行原有同步安全校验。

默认 60 秒兜底、监听失败时按 2 秒轮询，并在 30 秒后尝试重建监听；当前同步或重试操作可能延后扫描执行。网络故障试验仅作用于临时同步进程的连接，没有断开整机网络，也没有验证整机重启。本机结果不代表所有 Windows 版本和网络环境。

这些优化已纳入 v0.2.1 发布内容。复现单元测试使用 `python -X utf8 -B -m unittest discover -s tests -p "test_*.py"`；真实云端验证需要自行授权并使用独立测试目录。
