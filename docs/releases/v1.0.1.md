# 115Drive 1.0.1

修复同步历史目录缺失后任务中断、恢复目录后仍使用旧缓存的问题，并增加可选回收站策略。

## 同步修复

- 删除前先验证历史根和分片目录；历史目录缺失或被替换时，不先把源文件改成内部归档名称。
- 恢复历史目录后，从祖先目录刷新传输缓存，避免目录实际已恢复但创建分片仍失败。
- 保留原目录身份、任务、文件及同步数据库，未完成的旧事务仍按原协议恢复。

## 可选回收站策略

既有安装默认沿用 `retain`，不会因升级自动取消历史保留。需要停用长期云端历史时，
暂停全部任务并等待停止，在程序目录的 `config.json` 中设置 `"cloud_history_mode": "recycle"`，再恢复任务。
安装版、便携版和源码运行版均支持该设置。

此模式将同步删除项以及覆盖提交成功后的旧版本送入 115 回收站，不再建立长期云端历史目录。
上传仍先暂存和核验；提交未确认、响应丢失或并发冲突时保留必要正文和本机处理记录。
程序不会清空回收站。此设置不影响原有 bisync 任务；切换设置也不会自动删除既有历史目录。

## 验证

- 自动回归覆盖保留和回收站两种策略、只读访问、并发保护、暂停、中断和旧事务切换恢复。
- 独立真实云端验证覆盖原生文件随选新增、下载 SHA-1、覆盖、双向删除，以及中断后沿用原暂存 ID。
- 回收请求已完成但响应丢失时，重启核验来源位置，不重复按文件 ID 删除；并核对实际回收站条目。
- 历史目录缺失与缓存恢复分别通过独立云端检查；本机六任务恢复后的多轮检查正常。

发布包另经安装器与便携包逐文件比对、冻结模块与源码比对、校验清单和覆盖升级检查。
这些验证不代表物理断电、长期运行或服务端原子条件修改已经获得保证。
