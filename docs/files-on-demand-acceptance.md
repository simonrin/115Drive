## 修复

1. FULL hydration 使用完整 64 位文件长度；修复超过 4 GiB 时仅传回尾部 123 字节导致的原生参数错误。
2. 消除每个传输块的 ctypes 引用环，同样大文件场景的提供程序峰值工作集从约 429 MiB 降至约 28.5 MiB。
3. 用唯一暂存名和文件 ID 提交，保留旧版本；验证同名自动编号结果，避免检查后被另一客户端抢写而覆盖内容。
4. 持久化提交阶段和冲突退出状态；重启可越过自己的未完成事务扫描阻挡，恢复后继续核验。
5. Windows Job Object 绑定传输子进程，提供程序异常终止时不留下继续写云端的孤儿传输。
6. 保留 115 改名所需的扩展名；身份改名后刷新 OpenList 父目录缓存，修复提交成功后立即下载失败。

## 范围和升级约束

- “断电恢复”在本次以 `TerminateProcess` 强杀和进程重启模拟；没有切断整机电源，不能证明磁盘控制器或硬件缓存的物理掉电安全。
- 竞争客户端使用独立进程、独立状态和锁；验证同一账号真实云端内容，不声称覆盖所有第三方客户端实现或所有竞争时序。
- 新 CfAPI 任务保留替换/删除历史，会占用云端空间；暂不自动清理。此规则不修改旧 bisync 的配置。
- 升级先暂停旧任务，备份配置、登录状态、同步基线、续传/事务历史和旧程序，逐文件校验后恢复原暂停意图。不使用 `--resync`，不转换旧同步盘。
- 失败报告独立保存。生成的云端测试目录已清理；重复 4 GiB 样本完成核验后释放，报告及失败证据保留。
- 未覆盖大目录长期运行、全部用户文件库、整机物理掉电或硬件损坏。
